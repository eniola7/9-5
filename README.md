# LOLO

**LOLO is a behavioral trust layer for credit-invisible and credit-misunderstood consumers.**

LOLO is an early-stage fintech prototype that helps people build a clearer financial trust profile before traditional banks, lenders, landlords, and credit systems fully understand them. The product combines a consumer-facing trust profile, an educational LOLO Trust Score, financial behavior insights, simulation tools, and an AI-guided next-best-action experience.

This repository contains a demo-ready Expo / React Native app and a small Python prototype engine that generates realistic demo data for the frontend.

## Who It Is For

LOLO is designed for people whose financial reliability is not always captured well by traditional credit products:

- Recent immigrants with thin U.S. credit files
- Students building credit for the first time
- Early professionals with stable income but high utilization
- Renters trying to prove reliability
- Families working toward financial stability on constrained income
- Credit-visible consumers whose behavior is improving faster than their official score reflects

## The Problem

Credit scores are useful, but incomplete. They can miss context that matters:

- A person may pay rent reliably but have a thin credit file.
- A new professional may have stable income but look risky because of statement timing.
- A student may be building healthy habits before their credit age reflects it.
- A recent immigrant may have financial discipline that is invisible to U.S. credit systems.
- Families may be making responsible progress that is not easy to communicate to lenders or landlords.

LOLO explores how behavioral financial signals can help users understand, improve, and eventually communicate trust more clearly.

## Product Vision

LOLO starts as a consumer trust profile: a private, educational view of credit habits, cash flow, runway, spending behavior, and next-best actions.

Over time, LOLO could become infrastructure for consent-based trust signals between consumers and institutions. The long-term vision is not to replace official credit scores, but to add a clearer behavioral layer around them.

## Key Features

- **60-second guided demo:** meet a demo user, see their Trust Score, understand what changed, simulate an action, and receive an AI next-best-action.
- **LOLO Trust Score:** educational trust signal based on payment consistency, utilization control, cash flow stability, emergency runway, and spending behavior.
- **Demo user switching:** compare five realistic personas generated by the Python engine.
- **Dashboard:** Trust Score, credit health, cash flow, stress forecast, simulations, and recommendations.
- **Credit Profile:** utilization, payment history, factor breakdown, action plan, and engine-backed simulations.
- **Financial Insights:** spending drift, emergency runway, subscriptions, and recommended actions.
- **AI Coach:** suggested prompts and responses based on selected demo-user data.
- **Money Journal:** monthly reviews and reflection cards for financial milestones.
- **Demo presentation page:** lightweight explainer page for users, advisors, and investor conversations.
- **Auth entry points:** polished login, signup, forgot password, and profile creation placeholder flows.
- **User profile page:** profile summary, badges, privacy settings, journal entries, and saved reviews.
- **Python engine:** local prototype engine for demo users, scoring, recommendations, simulations, and JSON export.

## Python Engine

The Python prototype engine lives in [lolo-engine](lolo-engine).

It includes:

- `demo_users.py`: five fictional demo users
- `trust_score.py`: transparent educational scoring model from 300 to 850
- `recommendations.py`: personalized next-best-action generation
- `simulations.py`: action simulations such as card payments, spending reductions, income changes, emergency savings, missed payments, and inquiries
- `export_demo_json.py`: exports `sample_output.json` for the app

Regenerate the frontend demo data:

```bash
cd lolo-engine
python3 export_demo_json.py
```

Validate the generated JSON:

```bash
python3 -m json.tool sample_output.json
```

## Trust Score Disclaimer

LOLO Trust Score is an educational demo score for product prototyping. It is not a FICO score, VantageScore, credit bureau score, underwriting model, lending decision, or financial advice.

The current score is intended to make product behavior understandable in a demo. A production scoring model would require deeper validation, compliance review, user consent, security review, adverse-action considerations, and partner-specific evaluation.

## Privacy-First Positioning

Current prototype:

- Uses demo data only
- Does not store real financial data
- Does not connect to banks, Plaid, credit bureaus, payroll, lenders, or OpenAI
- Does not make real credit or lending decisions

Future product:

- Financial integrations should require explicit user consent
- Users should understand what data is connected and why
- Educational trust signals must remain clearly distinct from official credit scores
- Any partner or lender layer would require compliance, privacy, and security review

## Auth Status

LOLO is structured for Auth0 as the authentication provider. In this Expo prototype, auth screens use Auth0-ready placeholder flows so the app remains portable without native Auth0 configuration.

Required Auth0 environment placeholders:

```bash
AUTH0_SECRET=
AUTH0_BASE_URL=http://localhost:3000
AUTH0_ISSUER_BASE_URL=
AUTH0_CLIENT_ID=
AUTH0_CLIENT_SECRET=
EXPO_PUBLIC_AUTH0_DOMAIN=
EXPO_PUBLIC_AUTH0_CLIENT_ID=
```

Auth0 owns authentication. MongoDB should store only LOLO app data such as profile fields, preferences, journal entries, reviews, and financial snapshots. Do not store Auth0 passwords in MongoDB.

For production Expo / React Native:

- Configure Auth0 Universal Login or Auth0 React Native with Expo-compatible callbacks.
- Keep `AUTH0_CLIENT_SECRET` server-side only.
- Use Auth0 user `sub` as `auth0UserId` on LOLO profiles.
- After login, fetch or create the LOLO profile in MongoDB.
- Route users without profiles to profile onboarding.

Production next steps:

- Add a server runtime for protected API routes
- Implement Auth0 session validation on API requests
- Never store plaintext passwords or Auth0 secrets in the frontend
- Add protected API routes for users, profiles, journal entries, reviews, and financial snapshots

Planned API contract is documented in [src/lib/apiPlaceholders.ts](src/lib/apiPlaceholders.ts).

## For Investors / Advisors

LOLO is exploring a simple thesis: traditional credit scores are important, but they do not fully represent financial trust for many consumers.

Behavioral financial trust matters because users often improve before institutions can see that improvement. A person may become more consistent, reduce pressure, stabilize cash flow, or build runway before those changes are visible in traditional credit systems.

LOLO starts as a consumer product because users need to understand and improve their own financial trust first. If the trust profile becomes useful, the same consent-based layer could later support infrastructure use cases with landlords, lenders, banks, and other partners.

The current prototype is intentionally early. It is built to support user conversations, advisor feedback, and product validation without making real financial claims.
